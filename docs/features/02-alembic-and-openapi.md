# Feature 1b: Alembic Migrations & OpenAPI Documentation

A continuation of the backend foundation (not a new numbered roadmap feature) — filling in two pieces that were explicitly deferred from Feature 1: schema migrations and production-grade API documentation metadata.

## What was built

- **`app/infrastructure/database/base.py`** — a SQLAlchemy `DeclarativeBase` (`Base`) for all future ORM models to inherit from.
- **Alembic**, configured with the async template, `script_location` pointed at `app/infrastructure/database/migrations/`:
  - `migrations/env.py` sources the DB URL from `app.config.get_settings()` (no URL duplicated in `alembic.ini`) and points `target_metadata` at `Base.metadata` for autogenerate.
  - `versions/` is empty — no ORM models exist yet, so there's nothing to migrate. The wiring itself is verified via `alembic current`.
- **OpenAPI metadata** in `app/main.py`: real `description`, `license_info` (Apache-2.0, matching the repo `LICENSE`), and `openapi_tags` (currently just `health`). `/docs`, `/redoc`, and `/openapi.json` are disabled automatically when `APP_ENV=production`.
- **`Settings.app_version`** — single source of truth for the version string now used by both the FastAPI app metadata and the health response.
- **`GET /api/v1/health`** now also reports `app_version`.
- **`backend/Dockerfile`** now also copies `alembic.ini` into the image, so migrations can be run against a container (`docker compose exec backend uv run alembic upgrade head`).

See `ARCHITECTURE.md` → "Database migrations (Alembic)" and "API documentation" for the reasoning.

## How to run it

```bash
cd backend
uv sync
uv run uvicorn app.main:app --app-dir src --reload
```

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Health (now includes `app_version`): `http://localhost:8000/api/v1/health`

Migrations:

```bash
uv run alembic current              # show current DB revision (none yet)
uv run alembic revision --autogenerate -m "add X"   # once models exist
uv run alembic upgrade head
```

Via Docker Compose:

```bash
docker compose up --build
docker compose exec backend uv run alembic current
```

## How to test it

```bash
cd backend
uv run pytest -v
uv run ruff check .
```

## Verification performed

- `uv run pytest -v` — still 1/1 passing (health test unaffected by the added `app_version` field)
- `uv run ruff check .` — clean
- `uv run alembic current` / `alembic history` — connects through the real async engine against the configured SQLite DB, no errors
- Dev server: `/api/v1/health` includes `app_version`; `/docs` returns 200; `/openapi.json` reports the correct title/version/license
- `APP_ENV=production` run: `/docs` returns 404, confirming docs are disabled in production
- `docker compose up --build`: container healthy, health endpoint correct, `docker compose exec backend uv run alembic current` succeeds against the containerized app

## Decisions worth calling out

- **`Base` was added now, with zero models**, purely because Alembic's autogenerate requires `Base.metadata` to exist. This is infrastructure wiring, not a placeholder domain model.
- **No baseline migration was generated.** An empty autogenerated migration would be a no-op file with nothing to justify it; the connection wiring is proven by `alembic current` instead.
- **Docs disabled in production** — a real, functioning behavior (not a TODO), gated on `Settings.app_env`.
